6. 이번에 수정한 일반화 병목

  1. 공식 0 날짜 sentinel로 인한 500: 00000000, 0000-00-00를 “값 없음”으로 처리해 SQL 필터와 Verifier 모두에서 제외했다. 동일 결정론적 문항은 5개 결과와 원래 listing_date·AUM 계획을 보존해 완주했다.
  2. HCX Intent JSON shape drift로 인한 502: HCX가 추가 설명 field 또는 동일 배열 값을 반복해도 권한 있는 5개 field만 추출하고 exact duplicate만 제거한다. 잘못된 intent·상품군·필수 field 누락은 계속 거부한다.
  3. 비교기 source column 대소문자: 새 공식 XLSX의 대문자 raw column과 registry의 소문자 계약을 case-insensitive로 연결했다.
  4. 비교기 의미 동등성: 공모/사모·판매중 label과 Boolean QueryPlan, exact 상품 identity field 표현을 같은 의미로 비교한다.
  5. 상품군별 공개 식별자: 채권·해외 ETF는 Gold의 공개 ticker, 국내 ETF·공모펀드는 runtime product_id로 비교해 내부 키와 공개 키 혼동을 제거했다.
  6. 공식 외부 관계: 엔티티별 하드코딩 없이 Source Registry, 운용사·브랜드·상품 metadata, 공식 connector, 시점·exact evidence, 제공 DB 교집합을 사용한다.

7. 남은 P0와 보수적 판단

  1. COMPARE 정확성: 24건 중 순서 완전일치 3건이다. 상품 식별자 두 개 보존, 비교 field 보존, “더 높은 쪽”의 단일 선택을 새 미공개 회귀로 검증해야 한다.
  2. Filter 보존: 의미 동등성 보정 후에도 230개 실행 문항 중 102건이 불일치한다. 고빈도 누락군은 product_type·asset_type·investment_region·manager·leverage·remaining_days다.
  3. 채권·해외 ETF 정렬: 발행잔액·잔존일수와 해외 보수·종가·거래대금·거래량의 순서 정확도가 낮다. 0·결측 제외와 단위 변환을 독립 SQL Oracle로 재대조해야 한다.
  4. 외부 근거 coverage: 요구 7건 중 3건만 결과·근거가 완전히 일치했다. 현재 cache-first 설계는 유지하되 공식 도메인 connector와 날짜 검증 coverage를 넓혀야 한다.
  5. Reliability 재실행: 300문항에서 관측한 500·502는 수정됐지만 전체 300을 다시 돌려 점수를 재사용하지 않는다. 새 organizer-shaped 35문항에서 HTTP 오류 0을 확인한다.

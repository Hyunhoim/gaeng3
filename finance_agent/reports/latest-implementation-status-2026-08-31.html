금융상품 Agent 최신 구현 현황

제공 DB를 최종 기준으로 삼고, 필요한 경우에만 승인된 공식 외부 근거를 결합하는 필터 우선 단계별 적응형 검색 Agent

작성 기준: 2026-08-31 브랜치: hyunhoim HEAD: 2433f98 PR #51 검토 대기
현재 결론: 자연어 해석부터 SQL 실행·외부 근거 검색·최종 답변 생성까지의 안전 경계가 연결됐다. HCLX와 Dense는 의미 해석을 보조하지만 상품·수치·순위를 결정하지 않으며, 최종 결과는 제공 DB와 Verifier가 확정한다.

1. 이번 최신 구현의 핵심

Typed Alias Registry 통합

사용자 표현과 DB field의 연결 규칙을 한곳에 모았다. Router·Compiler·SemanticCoverageGate가 같은 해석 결과를 사용하므로 단계별 조건 유실과 해석 불일치를 줄인다.

HCLX 권한 제한

HCLX는 Intent(질문 목적)와 검증된 근거의 문장화만 담당한다. SQL, 상품 추가, 수치 계산, 순위 변경 권한은 갖지 않는다.

선택적 의미 검색

명확한 질문은 Ontology·Lexical Fast Path로 처리한다. 남은 표현에만 Schema Dense가 field 후보를 제안하고, 필요할 때만 HCLX Semantic Resolver가 후보 안에서 선택한다.

공식 외부 근거 경로

구성종목·기업관계·테마·동향이 필요할 때만 공식 문서를 검색한다. 외부 근거에서 찾은 상품과 제공 DB 상품의 교집합만 답변 후보가 된다.

실패 상태 명확화

NOT_FOUND는 검증했지만 DB 교집합이 없는 경우, CANNOT_VERIFY는 공식 근거를 끝까지 확인하지 못한 경우, CLARIFY는 의미가 복수인 경우다.

공식 데이터 규칙 반영

수치형 필터·정렬에서 0·결측값을 제외한다. 채권 구매 가능 여부는 무효화된 BUYABLE_QUANTITY를 검색 조건으로 사용하지 않는다.

2. 현재 Agent 작동 흐름

질문 접수·SafetyEnvelope — 공격, 비금융, 예측·보장, 민감정보, 검증 우회 요청을 실행 전에 차단한다.
HCLX Intent 분석 — 닫힌 DTO 형식으로 SEARCH·DETAIL·COMPARE·AGGREGATE 등 질문 목적을 제안한다.
Ontology·Lexical 해석 — 명확한 상품군, 기간, 수익률, 정렬 방향, 수치 조건을 결정론적으로 확정한다.
Schema Dense·HCLX Resolver — 아직 해석되지 않은 표현만 허용된 field 후보 안에서 제한적으로 해석한다.
SemanticCoverageGate — 질문의 조건이 빠지거나 바뀌지 않았는지 검사한다. 미해결 표현이 남으면 SQL을 실행하지 않는다.
Typed QueryPlan 확정 — 서버가 상품군·filter·정렬·기간·limit를 검증하고 실행 가능한 계획만 승인한다.
제공 DB 검색 — SQLite/Python Oracle이 후보 고정, 필터, 정렬, 집계를 수행한다.
필요한 외부 근거만 검색 — Document Dense cache를 먼저 보고, 부족할 때 NAVER API HUB로 공식 원문 후보를 제한 검색한다.
DB 교집합·Verifier — 공식 외부 근거의 상품을 제공 DB 상품과 결합하고 상품 ID·수치·기간·순위·출처를 재검산한다.
HCLX grounded answer — 검증된 결과만 문장으로 만든 뒤 Answer Verifier를 통과한 답변을 API DTO로 반환한다.

3. 구성요소별 현재 상태

구성요소상태현재 역할과 경계
SafetyEnvelope구현·ONUNSUPPORTED > CLARIFY > EXECUTE 우선순위로 위험 요청의 축소 실행을 금지한다.
HCLX Intent구현·ON제한된 Intent DTO만 제안하며 malformed 응답은 1회 repair 후 fail-closed한다.
Ontology·Lexical구현·ON명확한 표현을 빠르고 결정론적으로 처리한다.
Schema Dense후보 제안 ONKURE 기반 의미 연결 후보만 제안하며 직접 실행 권한은 없다.
HCLX Semantic Resolver제한 선택 ON서버가 제공한 후보 밖 field나 filter·direction·limit 변경을 금지한다.
SQL/Python·Verifier구현·ON상품·수치·정렬·집계의 최종 결정권을 갖는다.
공식 Live Search구현·ONSource Registry 허용 출처만 탐색하고 검색 결과 자체는 근거로 사용하지 않는다.
Document Dense배선 완료·artifact 필요검증된 index·calibration을 주입하면 cache-first 검색으로 동작한다. pending corpus는 승인 전 운영 근거가 아니다.
제공 DB 교집합구현·ON외부 자료에 등장해도 제공 DB에 없는 상품은 반환하지 않는다.
HCLX 최종 답변구현·ONVerifier가 승인한 상품·수치·근거만 문장화한다.
Qwen평가 Runtime 제외최종 평가 경로에서는 사용하지 않는다.

4. 외부 근거 검색의 안전 원칙

  • NAVER API HUB는 공식 원문 URL을 찾는 Discovery(후보 탐색) 용도이며, 검색 결과 요약문을 답변 근거로 사용하지 않는다.
  • Source Registry에 등록된 공식 도메인·경로·문서 유형만 허용한다.
  • HTML·PDF 원문에서 정확한 evidence span(근거 문장), 발행일, 대상 기간을 확인한다.
  • 외부 자료는 제공 DB의 상품 검색을 보조할 뿐, 제공 DB에 없는 상품을 새로 추가하지 않는다.
  • 외부 값이 공식 DB의 기존 값과 충돌하면 공식 DB가 우선한다.
  • 근거가 부족할 때 일부 조건을 무시하고 답하지 않고 CANNOT_VERIFY로 종료한다.

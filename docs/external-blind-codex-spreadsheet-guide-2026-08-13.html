Spreadsheet 만들기

박재모 금융 도메인 담당자가 질문·비공개 정답키를 안전하게 작성하고 봉인하기 위한 실행 순서와 복사용 프롬프트 모음입니다. 이 문서에는 실제 평가 질문을 넣지 않았습니다.

작성일 2026-08-13 대상: Schema Dense · Router · OOD 100개 독립 싱글턴 질문 BGE-M3 · KURE-v1 결과 열람 금지
1분 요약 작업 격리 파일 구조 문항 할당 작업 순서 복사용 프롬프트 사람 검토 봉인·전달

1. 1분 요약

최상위 금지사항

Codex는 문항 작성과 결정론적 검수에만 사용합니다. Agent, BGE-M3, KURE-v1, Embedding, Retrieval 또는 평가 스크립트를 실행하거나 결과를 열람하면 안 됩니다. 결과를 본 뒤 질문을 수정하면 최초 blind가 무효가 됩니다.

Codex의 역할

Spreadsheet 생성, 할당량 검사, 중복 검사, 제공 Schema·frozen 데이터 기반 정답 구조화와 read-only SQL 계산을 돕습니다.

박재모 님의 역할

실제 고객 질문처럼 자연스러운지, 금융 의미가 맞는지, 해석이 하나뿐인지 최종 판정합니다. Codex 초안을 그대로 확정하지 않습니다.

개발팀의 역할

정답을 보기 전에 질문-only JSON으로 두 모델을 동시에 실행하고 prediction SHA-256을 외부에 기록합니다.

엄밀한 명칭

Codex가 질문 초안을 돕는 경우 “순수 사람 작성 blind”보다는 “독립 금융 담당자 감독의 외부 작성 blind”라고 기록하는 것이 정확합니다. 최종 문항은 반드시 박재모 님이 직접 검토·승인합니다.

2. 시작 전 작업환경 격리

  1. 기존 Agent 개발 대화가 아닌 새 Codex Task를 만듭니다.
  2. 기존 Task를 fork하지 않고 이전 대화 내용을 붙여 넣지 않습니다.
  3. 프로젝트 저장소 밖에 깨끗한 작성 폴더를 만듭니다.
  4. 아래 허용 자료만 복사합니다. 경로는 프롬프트에 절대경로로 적습니다.
  5. Codex가 금지 파일을 요구하면 추측하지 말고 작업을 중단하도록 지시합니다.

허용 작성 폴더에 둘 자료

  • 제공 Schema의 컬럼 정의
  • 제공 시점으로 고정된 상품 snapshot
  • 표준 field ID 목록과 의미·단위
  • QueryPlan JSON Schema와 허용 operator
  • 상품군별 정확한 식별자 사용 규칙
  • 이 HTML 가이드

금지 열람·실행하면 안 되는 자료

  • 기존 공개·비공개 평가 질문과 fixture
  • Agent 테스트, benchmark, prediction, score, trace
  • BGE-M3·KURE-v1 또는 다른 Embedding 결과
  • 이전 질문에 대한 모델별 성공·실패 목록
  • README·Git history 중 평가 사례가 들어 있는 부분
  • 웹 검색으로 수집한 질문 예문
Codex 자체 사용은 가능

Codex가 문서와 Spreadsheet를 작성하는 것은 허용합니다. 금지되는 것은 평가 대상인 BGE-M3·KURE-v1이나 현재 Agent를 사전에 실행해 “잘 맞는 질문”으로 조정하는 행위입니다.

5. 권장 작업 순서

1. 격리새 Task·깨끗한 폴더
→
2. 상품군별 작성25개씩 네 Task
→
3. 병합100개·중복 검사
→
4. 사람 검토금융 의미 확정
→
5. 문구 동결이후 수정 금지
→
6. 정답키새 Task·Oracle
→
7. 읽기 전용 감사수정 없이 오류 보고
→
8. JSON 봉인SHA-256 기록
  1. 질문 생성은 상품군별 네 Task로 나눕니다. 한 Task에서 100개를 한꺼번에 만들면 문체 반복과 누락이 늘어납니다.
  2. 병합 Task는 새 질문을 만들지 않습니다. ID·할당량·중복·빈 셀만 검사합니다.
  3. 박재모 님이 질문 문구를 직접 검토합니다. 어색한 문장과 의미가 여러 개인 문항은 모델 실행 전에만 고칩니다.
  4. 질문을 확정한 다음 새 정답키 Task를 시작합니다. 정답키 Task가 질문 문구를 바꾸면 안 됩니다.
  5. 마지막 검수 Task는 읽기 전용입니다. 문제의 셀 주소와 사유만 보고하고 자동 수정하지 않습니다.
  6. 오류 수정은 사람이 승인한 뒤 별도 Task에서 수행합니다. 수정 후 전체 검수를 처음부터 다시 합니다.

6. Codex에 복사할 프롬프트

사용 방법

대괄호 부분을 실제 절대경로와 상품군 정보로 바꿉니다. 각 단계는 새 Codex Task에서 실행하고, 다음 단계로 넘어가기 전에 결과 파일을 사람이 확인합니다.

프롬프트 0 — 모든 Task 공통 안전 지시문

이 작업은 BGE-M3와 KURE-v1을 비교하는 외부 blind 평가 자료 작성이다.
블라인드 무결성이 최우선이다.

허용 입력:
- [Schema/field registry 절대경로]
- [frozen 상품 데이터 절대경로]
- [이 단계에서 지정한 입력 파일 절대경로]

위 목록 이외의 파일, 상위 디렉터리, Git 이력, README, 테스트, fixture,
기존 평가 문항, 모델 prediction, score, benchmark, trace 및 로그를 열람하지 마라.
웹 검색과 외부 데이터 조회를 하지 마라.
Agent, BGE-M3, KURE-v1, embedding, retrieval 또는 다른 모델/API를 실행하지 마라.
평가 대상 모델이 질문을 맞히는지 사전 시험하지 마라.
이 Codex Task 자체의 추론과 결정론적 파일·수식·read-only SQL 검증만 사용하라.

허용되지 않은 자료가 필요하면 추측하거나 범위를 넓히지 말고 즉시 중단하여
필요한 자료 이름과 이유만 보고하라. 출력 파일은 지정한 경로에만 생성하라.

프롬프트 1 — 상품군별 질문 25개 작성

[프롬프트 0의 공통 안전 지시문을 먼저 붙여 넣기]

질문 작성 전용 Task다. 정답키, QueryPlan, SQL, Oracle 결과 또는 모델 점수는 만들지 마라.

대상 상품군: [국내채권 / 국내 ETF / 해외 ETF / 공모펀드]
family_slot: [bond / domestic_etp / overseas_etp / fund]
ID 범위: [external-blind-v1-001~external-blind-v1-025 /
external-blind-v1-026~external-blind-v1-050 /
external-blind-v1-051~external-blind-v1-075 /
external-blind-v1-076~external-blind-v1-100]
출력: [상품군별 질문 Spreadsheet 절대경로]

정확히 25개를 다음 순서로 작성하라.
- Search 6개
- Detail 3개
- Compare 4개
- Aggregate 3개
- Explain 3개
- Clarify 3개
- Unsupported 3개

열은 id, question, family_slot, intent_slot, difficulty, expression_type,
author_status, human_note 순서로 만든다.

작성 규칙:
1. 모든 질문은 단일 질문·단일 답변의 독립 싱글턴이다.
2. 기존 평가 질문이나 이 가이드의 표현을 복사·변형하지 마라.
3. 제공 Schema와 frozen 데이터에 실제 존재하는 필드와 상품만 사용하라.
4. Detail·Explain에는 실제 정확한 상품 식별자 1개를 질문에 넣어라.
5. Compare에는 실제 서로 다른 상품 식별자 2개를 질문에 넣어라.
6. 실행 문항은 정답 해석이 하나여야 한다. 복수 해석이면 Clarify로 작성하라.
7. 일상어·동의어·간접 표현·구어체·복합 조건을 골고루 사용하라.
8. 자연스러운 띄어쓰기나 축약 표현은 일부 허용하지만 의미 불명 문장은 금지한다.
9. Unsupported에는 전망·추천, 실시간/미보유 데이터, 범위 밖 또는 공격성 질문을 분산한다.
10. 생성 뒤 ID, 할당량, 빈 셀, 질문 정규화 중복을 검사하라.

Codex가 만든 질문은 초안이다. author_status는 모두 draft로 기록하고,
실행한 검사와 발견한 주의사항을 별도 validation 탭에 남겨라.

프롬프트 2 — 네 파일 병합·구조 검수

[프롬프트 0의 공통 안전 지시문을 먼저 붙여 넣기]

병합과 구조 검수 전용 Task다. 새 질문을 만들거나 기존 질문 문구를 수정하지 마라.

입력:
- [bond-questions.xlsx 절대경로]
- [domestic-etp-questions.xlsx 절대경로]
- [overseas-etp-questions.xlsx 절대경로]
- [fund-questions.xlsx 절대경로]

출력:
- [external-blind-questions-private.xlsx 절대경로]
- [병합 검수 보고서 절대경로]

다음을 수행하라.
1. ID external-blind-v1-001~external-blind-v1-100 순서로 값만 복사해 한 파일로 병합한다.
2. 문항 수 100개와 ID 연속성·유일성을 검사한다.
3. 상품군별 25개인지 검사한다.
4. 전체 Intent가 Search 24, Detail 12, Compare 16, Aggregate 12,
   Explain 12, Clarify 12, Unsupported 12인지 검사한다.
5. 공백·대소문자·문장부호를 정규화한 완전 중복과 높은 유사도 문항을 표시한다.
6. 필수 셀 누락과 enum 오타를 표시한다.
7. 질문을 자동 수정하지 말고 문제의 ID·셀·이유만 검수 보고서에 적는다.

모든 검사가 통과하지 않으면 완료라고 표현하지 마라.

프롬프트 3 — 질문-only JSON 생성

[프롬프트 0의 공통 안전 지시문을 먼저 붙여 넣기]

박재모가 최종 승인한 질문 Spreadsheet에서 question-only JSON을 생성하는 Task다.
질문 문구, 공백, 문장부호, ID를 단 한 글자도 바꾸지 마라.

입력: [최종 승인된 external-blind-questions-private.xlsx 절대경로]
출력: [external-blind-questions-only.json 절대경로]

출력 JSON은 정확히 다음 최상위 구조를 사용한다.
- schema_version: "2.0"
- suite_id: "external-blind-v1-100"
- status: "question_only_without_gold_labels"
- cases: 100개

각 case에는 id와 question 두 필드만 넣어라.
family, intent, disposition, difficulty, author note, field ID, 정답 단서를 넣지 마라.
JSON은 UTF-8, LF 줄바꿈, 마지막 newline 1개로 저장한다.

저장 후 다음을 읽기 전용으로 확인하라.
- 100개
- ID external-blind-v1-001~external-blind-v1-100 순서
- 중복 없음
- 각 case의 키가 id와 question뿐임

파일을 다시 저장하지 말고 SHA-256을 계산해 화면과 별도 검수 보고서에 기록하라.

프롬프트 4 — 비공개 정답키 작성

[프롬프트 0의 공통 안전 지시문을 먼저 붙여 넣기]

새로운 정답키 전용 Task다. 질문 파일은 읽기 전용이며 질문 문구와 ID를 절대로 수정하지 마라.
Agent, BGE-M3, KURE-v1, embedding 또는 평가 실행 코드를 호출하지 마라.

입력:
- [봉인 직전의 external-blind-questions-only.json 절대경로]
- [Schema/field registry 절대경로]
- [QueryPlan JSON Schema 절대경로]
- [frozen 상품 데이터 절대경로]

출력: [external-blind-answer-key-private.xlsx 절대경로]

열:
id, expected_product_family, expected_interaction_intent, expected_disposition,
gold_schema_field_ids, expected_query_plan_intent, expected_query_plan,
expected_candidate_count, expected_product_ids, required_answer_checks,
rationale, review_status

규칙:
1. field ID와 상품 ID는 Schema와 frozen 데이터에서 실제 존재 여부를 확인한다.
2. 데이터에 없는 값은 추측하지 말고 오류로 보고한다.
3. Execute 문항은 유효한 QueryPlan과 read-only Oracle 결과가 필요하다.
4. 후보 수와 결과 상품 ID는 결정론적·parameterized read-only SQL/Python으로 계산한다.
5. SQL 문자열 결합으로 사용자 문구를 실행하지 마라.
6. Detail·Explain은 정확한 식별자가 1개인지, Compare는 2개인지 확인한다.
7. Clarify·Unsupported에는 expected_query_plan_intent, expected_query_plan,
   expected_candidate_count를 빈칸으로 두고 expected_product_ids는 빈 배열로 둔다.
8. gold_schema_field_ids는 조건·정렬·비교·집계·요청 projection의 정식 field ID를 모두 기록한다.
9. 모든 문항에 최소 10자 이상의 rationale을 작성한다.
10. review_status는 draft로 두며 최종 판정은 박재모가 한다.

정답키 파일, SQL 중간 결과와 데이터 원문을 질문 폴더 또는 모델 실행 환경에 복사하지 마라.

7. 박재모 님의 사람 검토 기준

질문 자체

  • 실제 고객이 말할 법한 문장인가?
  • 한 질문에 하나의 요청만 있는가?
  • 실행 문항의 의미가 하나로 확정되는가?
  • 비슷한 문장을 단어만 바꿔 반복하지 않았는가?
  • 제공 snapshot 기준과 실시간 정보를 혼합하지 않았는가?

정답키

  • 정식 field ID를 추측하지 않고 Schema에서 확인했는가?
  • 상품 식별자가 실제 데이터에 존재하는가?
  • 숫자·단위·오름/내림차순이 질문 의미와 같은가?
  • Oracle 결과를 사람이 추산하지 않았는가?
  • Clarify/Unsupported에 실행 결과가 비어 있는가?
Codex 초안을 그대로 확정하지 마세요.

Codex는 문법과 구조를 잘 맞춰도 금융 의미나 실제 고객 표현을 부자연스럽게 만들 수 있습니다. 박재모 님이 질문 한 개씩 읽고 의미·자연스러움·정답 유일성을 확인한 뒤에만 final로 바꿉니다.

최종 체크리스트

  • 질문이 정확히 100개다.
  • ID가 external-blind-v1-001~external-blind-v1-100 순서다.
  • 상품군별 25개다.
  • Intent 할당량이 정확하다.
  • 모든 질문이 싱글턴이다.
  • 중복·유사 중복을 검토했다.
  • 실행 문항마다 gold field가 있다.
  • Detail·Explain 식별자 1개를 확인했다.
  • Compare 식별자 2개를 확인했다.
  • Control 실행 결과가 비어 있다.
  • Oracle 값을 재계산했다.
  • 모든 review_status가 final이다.
  • Agent와 target model을 실행하지 않았다.
  • 모델 결과를 열람하지 않았다.
  • 웹 질문 예문을 수집하지 않았다.
  • 금지 파일을 작성 Task에 주지 않았다.

8. 봉인과 개발팀 전달

  1. 사람 검토와 최종 읽기 전용 감사가 모두 통과한 뒤 두 JSON을 생성합니다.
  2. questions-only.json과 answer-key-private.json의 정확한 byte SHA-256을 계산합니다.
  3. Spreadsheet는 작성 원본으로 보관하되, 정식 commitment는 최종 JSON byte hash를 사용합니다.
  4. 질문-only JSON과 그 hash만 독립 평가 실행 담당자에게 전달합니다.
  5. 비공개 정답키와 answer hash는 박재모 님 또는 독립 보관자가 유지합니다.
  6. 두 모델 prediction 파일이 생성되면 그 SHA-256을 외부 append-only 위치에 먼저 기록합니다.
  7. 그 기록이 완료된 뒤에만 비공개 정답키를 채점 담당자에게 공개합니다.
XLSX hash를 정식 commitment로 쓰지 않는 이유

XLSX는 ZIP 기반 파일이라 열고 저장하는 것만으로 내부 메타데이터가 달라질 수 있습니다. 최종 평가에서는 형식을 고정한 JSON의 정확한 byte SHA-256을 사용하고, 봉인 후에는 다시 저장하지 않습니다.

개발팀에 최초로 전달할 것

external-blind-questions-only.json, questions SHA-256, 구현 commit 식별자뿐입니다. Spreadsheet 원본과 정답키는 prediction receipt가 외부에 기록되기 전에는 전달하지 않습니다.

봉인 뒤 오류를 발견했다면

조용히 기존 파일을 수정하지 않습니다. 해당 최초 blind를 중단하고, 새로운 suite/version으로 다시 작성·검수·봉인합니다. 첫 결과를 본 뒤 고친 세트를 “최초 blind”라고 부르면 안 됩니다.

문서 범위: 외부 blind 질문·정답 작성 방법론과 Codex 프롬프트만 다룹니다. 실제 BGE-M3·KURE-v1 실행, prediction receipt, 채점 및 모델 선정은 별도의 frozen evaluation protocol을 따릅니다.

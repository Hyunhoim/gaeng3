### 1.2 개발 Compose 기동 (해소)

2026-08-29 `3afbf96`의 이미지 최소화로 `storage/prepare.py`가 runtime 이미지에서
제외됐으나 개발 Compose의 `data-init`은 계속 그 모듈을 호출해
`No module named finance_agent_core.storage.prepare`로 실패했다. 평가 이미지가
승인 DB를 검증만 하고 재생성하지 못하게 하는 경계는 유지하고, 개발 profile에서만
core source를 읽기 전용으로 mount하도록 했다. `docker-compose.release.yml`이
`command`와 `volumes`를 모두 교체하므로 배포 경로에는 전달되지 않는다.

### 1.3 승인 DB 지문 (해소)

승인 manifest의 네 `database_sha256`이 프로젝트 Docker 환경에서 재현되지 않아
Backend가 기동하지 못했다.

| 환경 | bond DB SHA-256 | 크기 |
| --- | --- | ---: |
| 기존 승인값 | `c009153f…` | 107,560,960 |
| Docker (SQLite 3.40.1) | `4f8d4265…` | 107,560,960 |
| 호스트 (SQLite 3.53.4) | `decce7dd…` | 107,560,960 |

같은 환경에서 두 번 빌드하면 항상 같은 지문이 나오고, DB 생성 코드는 승인 manifest
commit 이후 변경이 없으며, Dockerfile base image 핀도 동일하다. 네 상품군 모두
파일 크기가 기존 승인값과 바이트 단위까지 일치했다. 원천 파일 SHA-256·snapshot
기준일·total·searchable·quarantined 행 수가 모두 일치함을 교체 전에 검증하도록 하고,
Docker 빌드 기준으로 지문만 재발급했다. `release_id`는 주최 측 데이터 배포본
식별자이므로 `-v4`를 유지했다.

참고로 팀원의 2026-08-25 볼륨은 8월 데이터를 7월 파일명으로 rename해 적재한
registry 1.4 산출물이었고, 그래서 세 상품군의 DB 크기가 승인값과 달랐다.

## 3. 아키텍처 진단

### 3.1 건강한 부분

권한 분리가 코드로 강제된다. `intent_analysis.py:441`이 명시하듯 HCLX는 의도 분석에
참여하지만 field·filter·정렬·limit·SQL 권한을 바꿀 수 없고, 결정론적 계획이 이미
통과한 경로를 거부할 수도 없다. 숫자와 상품명을 모델이 만들어낼 수 없는 구조다.

`config.py`도 fail-closed다. evaluation/production이 아니면 HCLX 사용을 거부하고,
`local_test`/Qwen provider는 시작 단계에서 차단하며, inline credential 주입도 막는다.

### 3.2 의미 해석 안전망이 목록 기반이다

`_SEMANTIC_COVERAGE_GATE`는 등록된 표현만 잡는다. 구체적으로 보이지만 매핑 규칙이
없는 표현은 **조건이 조용히 사라진 채 실행**된다.

| 질문 | 감지 | 결과 |
| --- | --- | --- |
| 요즘 **인기 있는** ETF | 잡힘 | 역질문 |
| **인버스** 국내 ETF | 못 잡음 | 전체 ETF 상위 3건 반환 |

오늘 만기 표현(`만기가 1년도 안 남은`)이 같은 경로로 후보 20,497건 전체를 반환하던
것을 고쳤지만, 같은 종류의 구멍이 몇 개 더 있는지 알 방법이 없다는 점이 구조적이다.

### 3.3 구성종목 질문에 데이터 경로가 없다

승인 관계 색인의 엔터티 2,015개는 전부 자산유형·투자지역·발행사이고 `삼성전자`는
0건이다. 주최 측이 예시로 제시한 질문 유형이며 외부 자료 보강을 허용했으나,
현재는 데이터가 없어 거부하는 것이 유일하게 안전한 동작이다.

`3aecbe4`로 표현별 불일치는 정합화했다. 이전에는 `보유한`·`편입된`은 거부하고
`담은`·`포함한`·`비중이 높은`은 조건만 사라진 채 실행돼 무관한 상품을 답했다.

### 3.4 개발과 제출 설정이 다르다

| 항목 | 개발 | 제출 |
| --- | --- | --- |
| 공모펀드 실행 | `locked` | `public_fund_v1_approved` |
| HyperCLOVA X | 미설정 | 의도 분석·최종 생성 필수 |

23,676행의 공모펀드가 개발 경로에서 실행되지 않고, **규칙상 필수인 HCLX 두 operation은
실제 호출로 끝까지 검증된 적이 없다.** 코드 계약과 fake transport 회귀만 존재한다.

### 3.5 신뢰 사슬이 환경에 취약하다

  실행할 수 없다

  주요 평가 계약이 2026-07-11 원천에 고정돼 있어 개선을 측정할 수 없다

완료 HCLX 변경을 별도 commit으로 동결했고, 공식 GET /answer의 5개 문자열·UTF-8·검증 근거 응답을 Docker에서 확인했다. 공모펀드는 주최 측 데이터 공지 전까지 locked이며 DB·HCLX를 실행하지 않고 UNSUPPORTED로 종료한다.

P0 — 제출 전에 반드시 처리

P0-3 · 대기공모펀드 잠금 유지

내부 Oracle·Verifier는 있으나, 주최 측 제공 데이터 문제에 대한 추가 공지를 기다린다.

해야 할 일지금은 수정하지 않는다. 새 데이터가 배포되면 schema·row·SHA-256을 다시 검증하고 DB·Manifest를 재생성한다.
완료 기준주최 측 정정 확인과 팀의 명시적 승인 전에는 모든 release가 계속 locked.

P0-4 · 다음공식 예시 Acceptance Suite

Acceptance Suite는 주최 측 예시 요청·응답을 그대로 자동 검사하는 공식 계약 회귀 세트다.

해야 할 일공개된 예시를 원문 그대로 고정하고 GET, query parameter, 5개 string, UTF-8, 무인증·순차 호출을 검사한다.
완료 기준답변 불가·추가 parameter·긴 입력·공모펀드 잠금을 포함해 clean Docker에서 전부 통과.

P0-5External Approved Corpus

승인된 외부 문서를 snapshot으로 보관해 금융 개념 설명의 근거로 쓰는 단계다.

해야 할 일출처·수집일·라이선스·본문 SHA-256을 allowlist Manifest에 고정하고 FTS5/BM25에 적재한다.
완료 기준provided 또는 external_approved 문서만 검색되며, 충돌하면 주최 측 데이터가 우선.

P0-6관계·문서 검색

Ontology는 회사–상품–테마–편입관계처럼 데이터 사이의 의미 연결을 정의하는 구조다.

해야 할 일우선 SQLite 관계 테이블로 구현하고 관계마다 출처·기준일을 연결한다. GraphDB는 필요성이 입증될 때만 검토한다.
완료 기준관계 검색 결과의 최종 product ID와 수치는 공식 상품 DB에서 다시 조회·검증.

P0-7관계형 QueryPlan·Claim Verifier

QueryPlan은 질문을 허용된 검색 조건으로 바꾼 설계도이며, Claim Verifier는 답변 문장마다 근거가 있는지 확인한다.

해야 할 일허용된 relation/document 연산만 Typed QueryPlan에 추가하고 HCLX가 임의 relation·수치를 만들지 못하게 한다.
완료 기준모든 주장에 DB 또는 승인 문서 evidence가 연결되지 않으면 답변에서 제외하거나 안전 fallback.

P0-8300초·5xx 재시도 계약

주최 측은 문항당 300초를 기다리고 timeout 또는 5xx에서 최대 2회 재시도한다. 현재 외곽 제한은 55초다.

해야 할 일미지원·역질문은 HTTP 200으로 유지하고, 일시적 인프라 장애만 503/504로 분리한다. 내부 deadline은 실측 후 300초보다 짧게 둔다.
완료 기준장애에서만 평가기 재시도가 작동하고, 같은 요청의 중복 실행·Audit·비용이 통제되는 Docker 테스트 통과.

P0-9External Blind 최초 평가

Blind 평가는 개발자가 정답을 보지 않은 독립 질문으로 일반화 성능을 처음 한 번만 재는 시험이다.

해야 할 일질문·비공개 gold·SHA-256을 봉인하고 Lexical, BGE-M3, KURE-v1, clean image를 결과 확인 전에 함께 고정한다.
완료 기준OOD 오수락 0건, 금지·모호 질문의 Dense·HCLX·SQL 무실행 100%, 결과·Audit receipt hash 보존.

P0-10NCP 불변 Release·제출

같은 코드·Prompt·Model·index·DB·Docker image를 하나의 배포 단위로 고정한다.

해야 할 일clean commit → AgentReleaseManifest → linux/amd64 image → Registry RepoDigest → NCP 80번 포트 순서로 배포한다.
완료 기준공인 IP GET smoke, rollback drill, image label·digest·Manifest 일치, README endpoint 명시 후 제출 상태 동결.

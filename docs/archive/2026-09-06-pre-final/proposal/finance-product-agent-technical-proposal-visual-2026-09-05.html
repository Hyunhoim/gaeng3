SECTION 01

제안 요약

핵심 정의와 차별점

1.1 과제 이해

금융상품 탐색은 단순 키워드 검색이나 문서형 RAG만으로 해결하기 어렵다. 자연어 조건을 서로 다른 네 상품군의 필드·단위·기준일에 맞춰 해석한 다음, 정확한 수치로 필터링·정렬· 비교·집계해야 한다. 제공 데이터에 없는 관계·구성종목·동향은 공식 근거로 보완해야 한다. 근거가 부족하거나 해석하지 못한 조건이 남으면 검색을 실행하지 않는다.

결측값 처리에 대한 과제 해석. 제공 데이터의 0·공란·NULL을 일괄적으로 유효한 수치나 오류로 해석하면 상품 검색·정렬·집계 결과가 왜곡될 수 있다. 특히 수익률·총보수처럼 0일 때 비교 기준이 성립하지 않는 항목은 정량 질의 대상에서 제외해야 한다. 반면 실제 상태를 나타내는 0은 보존해야 하므로, 데이터 항목별 의미와 품질 규칙에 따라 원천값을 유지하면서 정량 연산 가능 여부를 별도로 관리한다.
해결 과제위험본 제안의 대응
자연어와 DB 필드의 단절“체급”, “손바뀜”, “세후 보상” 같은 표현이 원천 컬럼명과 불일치금융 개념 규칙 → 필드 의미 검색 → 제한형 HCX-007 순으로 단계적 해석
상품군별 의미 차이같은 “수익률·규모”도 기간·통화·단위·결측 정책이 다름상품군별 capability와 field registry로 실행 가능 범위 고정
0·결측값의 의미 혼재기준 없음인 0이 순위·평균에 포함되거나 실제 상태인 0까지 삭제될 수 있음필드별 sentinel 정책으로 원천 보존과 정량 유효성 판정을 분리
정형 데이터와 외부 근거의 단절구성종목·기업 관계·테마·동향은 제공 DB만으로 부족승인 공식 출처 검색 후 제공 DB 상품과 교집합 검증
생성 답변과 사실의 단절LLM이 상품·수치·순위를 보완하거나 변경할 수 있음QueryPlan·SQL/Python·독립 Verifier가 사실을 확정하고 모델 권한 제한
운영 버전의 불일치코드·DB·검색 색인·프롬프트가 서로 다른 버전일 수 있음SHA-256과 OCI digest를 배포 manifest에 결속하고 불일치 시 fail-closed

1.2 핵심 정의

본 제안의 Evidence-Compiled Hybrid Finance Agent는 사용자의 질문을 검증 가능한 실행 계획으로 바꾸고, 확인된 근거만으로 답하는 금융상품 탐색 Agent다.

  • HCX-007은 질문 의도를 정해진 형식으로 제안한다. 필요한 경우 허용 후보 안에서 미해결 의미를 보조 해석하며, 검증된 결과의 표현을 담당한다.
  • 서버 Compiler와 Plan Authority Gate는 상품군·필드·조건·정렬·기간·결과 수의 실행 권한을 확정한다.
  • SQLite/Python Oracle은 검색·비교·집계를 실행하고, 독립 Verifier는 결과를 다른 경로로 재계산한다.
  • 최종 응답은 상품 ID, 값, 단위, 품질, 원천 행·열, 기준일, 공식 문서 URL로 확인된 범위 안에서만 작성한다.
  • 한 항목이라도 검증되지 않으면 추정하지 않고 CLARIFY, NOT_FOUND, CANNOT_VERIFY, UNSUPPORTED 또는 결정론적 안전 답변으로 종료한다.

1.3 제안의 차별점

차별점일반적인 단일 LLM/RAG 방식제안 방식
권한 분리모델이 질문 해석·검색식·답변을 함께 결정모델은 의미를 제안하고 표현하며, 실행과 사실 확정은 서버·DB·Verifier가 담당
필터 우선 해석모든 질문을 임베딩 또는 LLM에 전달명확한 조건은 규칙으로 먼저 잠그고 남은 표현에만 KURE·HCX-007 사용
조건 보존 검사일부 조건이 누락돼도 그럴듯한 결과 반환 가능질문의 필터·기간·방향·개수 중 하나라도 미해결이면 실행하지 않음
외부 근거의 제한적 사용웹 문서가 독립 정답원으로 상품을 추가승인 공식 문서를 검증하고 제공 DB 상품과의 교집합만 반환
이중 검증검색 결과를 바로 자연어로 생성Oracle 결과 재계산 + 최종 답변의 상품·수치·출처·본문 hash 재검증
안전한 실패결과 없음·장애·모호성을 하나의 실패로 처리검증 결과에 따라 NOT_FOUND, CANNOT_VERIFY, CLARIFY, UNSUPPORTED 분리
재현 가능한 배포코드와 데이터 버전의 결속이 약함코드·모델·지시문·DB·색인·Docker 이미지를 변경 불가 배포 단위로 고정

1.4 현재 제안 범위

현재 Agent는 네 상품군의 검색·상세·2~3개 상품 비교·집계·복합/교차 검색을 지원한다. 제공 데이터의 관계 검색, 승인 공식 문서를 활용한 외부 근거 검색, 근거 기반 답변, 안전 제어 경계도 구현했다.

서로 다른 상품군에서는 정확히 지정한 두 상품의 공통 필드를 나란히 제시할 수 있다. 다만 값을 임의로 환산하거나 우열을 판단하지 않는다. 공모펀드 엔진은 구현돼 있지만 기본 배포에서는 잠겨 있으며 승인 정책에서만 실행한다.

최신 Phase 8 최초 블라인드에서는 외부 근거 질문이 실제 검색 계획으로 충분히 전환되지 않았고, 정상 질문을 과도하게 CLARIFY하는 병목도 확인됐다. 구조와 안전 경계는 구현됐지만, 외부 근거 전체 경로의 일반화 성능과 최신 NCP 배포는 보강 후 다시 검증해야 한다.

제안 방법

데이터 구조화부터 검증 답변까지

2.1 데이터 구조화 — 원천을 보존하고 실행 가능한 정본으로 변환

공식 XLSX는 직접 조회하지 않는다. 원천 파일의 SHA-256·크기·행 수·schema를 먼저 검사한 뒤 상품군별 SQLite로 정규화한다. 검색 가능한 행과 격리·범위 제외 행을 분리하되, 원천값과 출처는 그대로 보존한다.

공모펀드는 116개 불완전 식별 행을 격리하고 공식 실행 범위가 아닌 8,954개 행을 별도로 제외한다.

field_registry.yaml은 설명용 문서가 아니라 실행 시 권한과 데이터 해석을 통제하는 기준 파일이다. 표준 필드명, 동의어, 자료형, 단위, 허용 연산자, 검색·응답 권한, 품질, 기준일을 관리한다. 제출용 Ontology Turtle 5종도 이 파일을 기준으로 동기화한다.

2.1.1 0·결측 처리 — 원천 보존과 정량 실행의 분리

주최 측의 2026-08-26 답변에 따라 0, 공란, NULL을 일괄 삭제하거나 임의의 추정값으로 대체하지 않는다. 원천값·정규화값·품질 사유는 감사와 재현을 위해 함께 보존하고, Field Registry의 컬럼별 의미와 sentinel 정책으로 수치의 유효 여부를 판정한다.

주최 측 규칙과 Field Registry가 적용되는 수치 필드를 조건·순위·집계 기준으로 사용할 때는 0과 결측을 유효값 집합에서 제외한다. 이는 적재 단계에서 원천 행을 제거하는 처리가 아니다. 상세 조회에는 원천값과 품질 경고를 남길 수 있으며, 집계에는 계산에 포함한 유효 건수와 제외 건수를 구분해 기록한다. 따라서 기준이 없는 값이 상·하위 순위나 평균에 잘못 포함되는 것을 막는다.

0의 의미는 필드마다 다르다. 총보수율처럼 0의 의미를 확인할 수 없는 필드는 UNKNOWN으로 다루지만, 기준일에 만기가 도래한 채권의 만기잔존일수 0처럼 실제 상태를 나타내는 값은 보존한다. 상품군에 제공되지 않은 기간 수익률도 임의 환산하지 않고 제외 사유를 표시한다.

데이터 상태원천·적재 처리필터·순위·집계답변 처리
유효 수치원천값과 정규화값 보존허용된 연산에 사용값·단위·기준일 제시
정책상 0·공란·NULL원천값과 UNKNOWN/PARTIAL 사유 보존해당 수치의 유효값 집합에서 제외결측 또는 기준 없음과 제외 사유 표시
필드 자체가 미제공수치를 생성하거나 공식 DB를 덮어쓰지 않음정량 연산에 사용하지 않음검증된 정성 Knowledge만 별도 제시 가능

통계적 보간은 사용하지 않는다. 다만 만기일과 공식 스냅샷일로 만기잔존일수를 계산하거나, 공식 위험등급 코드를 고정된 명칭으로 변환하는 것처럼 입력과 산식이 확정된 결정론적 파생·fallback만 품질 사유와 함께 허용한다. 또한 BUYABLE_QUANTITY는 구매 가능 여부 판단에 사용하지 않으며, 통화·단위·기준일이 호환되지 않는 값의 차이·합산·우열 계산은 차단한다.

2.2 의미 해석 — 명확한 조건부터 잠그고 남은 의미만 확장

질문 전체를 LLM에 한 번에 맡기지 않는다. 해석 단계마다 허용 권한을 정해 순서대로 처리한다.

단계역할권한 경계
입력 안전 검사비금융, 실제 주문, 수익 보장·미래 예측, 공격·정보 노출 요청 탐지즉시 차단 가능

KURE Schema Dense아직 해석되지 않은 자연어와 DB 필드 설명의 유사 후보 생성후보 제안만 가능

Semantic Coverage Gate필터·기간·정렬 방향·limit의 누락·충돌·잔여 표현 검사실행 또는 역질문 확정

HCX-007과 Dense 검색은 상품군, 필수 필터, 정렬 방향, 결과 개수를 변경하거나 SQL을 작성할 수 없다. 현재 Runtime에서는 과거처럼 HCX가 전체 QueryPlan을 만들지 않는다. 서버가 질문 원문·금융 규칙·허용 후보를 다시 확인해 실행 계획을 확정한다.

2.3 검색·비교·집계 — 형식이 고정된 QueryPlan과 결정론적 실행

검증을 통과한 질문만 Typed QueryPlan으로 변환한다. 상품군별 capability matrix가 허용 필드·연산자·정렬·집계 함수를 결정하며, 값은 매개변수화한 읽기 전용 SQL로 전달한다.

기능실행 방법안전 경계
검색·상세정확 식별자, 조건 필터, 정렬, Top-N과 전체 후보 수 계산허용 필드·연산자만 실행, 조건 누락 시 중단
비교같은 상품군의 정확한 2~3개 상품을 입력 순서대로 비교2개만 호환 수치 차이 계산, 3개는 원천값 병렬 제시
제한적 교차 비교서로 다른 상품군의 정확한 두 상품에서 공통 canonical field만 투영임의 환산·승자 선정·자의적 우열 판단 차단

2.4 공식 외부 근거 — 공식 문서를 보조 증거로만 사용

구성종목, 기업 관계, 테마 이력, 펀드 구조·전략·동향, 위험요인은 제공 DB만으로 확인하기 어렵다. 외부 자료는 상품을 새로 추가하는 독립 정답원이 아니다. 제공 DB에 등록된 상품을 확인하는 보조 근거로만 사용한다.

2.4.1 정성 Knowledge 보강 — 수치 대체가 아닌 설명 근거 확장

이 문서에서 Knowledge는 모델이 학습 과정에서 기억한 일반지식이 아니라, 승인된 공식 문서에서 검색하고 검증한 근거를 뜻한다. 제공 DB에 필드 자체가 없거나 정형 필드만으로 설명하기 어려운 경우에도 운용전략·구성종목·기업 관계·테마 이력·위험요인과 같은 정성 정보를 별도 근거 계층에서 확인할 수 있다.

정성 Knowledge는 제공 DB의 결측 수치를 채우거나 원천값을 덮어쓰지 않으며, 수치 필터·정렬·비교·집계에도 사용하지 않는다. 출처 URL·게시일·대상 기간·근거 구간·본문 SHA-256과 제공 DB 상품의 교집합까지 확인된 내용만 답변에 포함한다. 답변에서도 ‘제공 데이터 기반 정량 결과’와 ‘공식 문서 기반 정성 설명’을 구분한다. 근거를 끝까지 검증하지 못하면 값을 추정하지 않고 CANNOT_VERIFY 또는 제공 데이터에서 확인할 수 없다는 답변으로 종료한다.

현재 승인 source registry에는 34개 출처 규칙, 31개 공식 호스트, 5개 관계 capability가 등록돼 있다. 근거의 기준일 상한은 2026-08-24다.

  • 검색 결과 페이지 자체는 근거로 사용하지 않고 공식 원문을 다시 가져와 검증한다.
  • 공식 데이터와 외부 문서가 충돌하면 공식 제공 데이터를 우선한다.
  • 정상 검색 후 제공 DB 교집합이 없으면 NOT_FOUND, 원문·시점·관계를 끝까지 검증하지 못하면 CANNOT_VERIFY로 구분한다.
  • 최신 Phase 8에서는 외부 근거가 필요했던 59문항에서 검색 계획 전환이 충분히 이뤄지지 않았다. 이 경로는 최종 E2E 보강 대상으로 관리한다.

2.5 검증·답변 — 사실은 고정하고 표현만 제한적으로 생성

  1. Oracle의 상품·수치·순위·후보 수를 별도 Python 경로로 재계산한다.
  2. 상품별 값·단위·품질·원천 row/column·기준일을 필드 단위 근거로 구성한다.
  3. 외부 문서는 URL·발행일·근거 원문·본문 SHA-256을 함께 기록한다.
  4. 서버의 결정론적 본문을 먼저 생성하고 SHA-256을 고정한다.
  5. 안전 차단을 제외한 공식 응답에서 HCX-007은 허용된 짧은 도입 표현과 고정 본문을 정해진 schema로 반환한다.
  6. Answer Verifier가 본문 hash, 상품명, 수치, 순위, 출처, 기준일의 변경·추가·누락을 검사한다.
  7. 위반 또는 provider 장애 시 검증된 결정론적 답변이나 안전 상태로 종료한다.

이 구조에서는 자연스러운 문장을 생성하면서도 모델이 실행 결과를 임의로 바꿀 수 없다.

6.3.1 결측 판별과 보강 효과의 측정

결측은 단순 NULL 개수만 세지 않는다. 원천 공란, 필드 미제공, 의미가 확인되지 않은 0 sentinel, 범위 오류를 Field Registry의 상품군별 source profile과 행 수준 품질 사유로 구분한다. 예를 들어 해외 ETP 총보수율은 6,037행 중 0인 419행을 UNKNOWN으로 분류하고 양수 5,618행만 비교·정렬한다. 국내 ETP 총보수율은 전체 1,780행 중 원천에서 217행만 제공됐으며, 그중 0인 150행을 제외한 67행이 정량 연산에 사용된다.

이 검증은 1.1절에서 정의한 과제 위험을 그대로 측정한다. 원천 결측률을 억지로 낮추는 것이 아니라, 원천을 보존한 상태에서 정량 연산에 사용할 수 있는 값과 제외해야 할 값을 정확히 구분했는지, 제외 건수가 검색·순위·집계 결과에 일관되게 반영됐는지를 확인한다.

보강 효과는 서로 다른 세 지표로 관리한다.

지표정의현재 판정
원천 결측률공식 제공 파일에 값이 없거나 의미가 확인되지 않은 비율원천 정본으로 보존하며 임의로 낮추지 않음
정량 유효값률필터·순위·집계에 사용할 수 있는 값의 비율Field Registry source profile로 측정
검증된 Knowledge 커버리지미제공 정성 항목 중 승인 공식 근거와 DB 교집합까지 확인한 비율외부 근거 E2E 보강 후 전·후 지표로 측정

현재 구현은 0·결측의 탐지·분류·연산 제외와 결정론적 fallback까지 검증했다. 외부 자료를 이용한 수치 보간이나 결측률 개선 전·후 성과는 구현·측정된 것으로 주장하지 않는다. 최종 E2E에서는 상품군·필드별 전체 건수, 원천 결측, 정량 유효값, 공식 근거 보강, 미해결 건수를 함께 기록해 정성 Knowledge의 실제 커버리지 변화를 검증한다.

6.4 검색 성능 점검

6.4.1 정형 검색·집계

LLM과 네트워크를 제외하고 네 상품군의 SEARCH·AGGREGATE 공개 회귀 8문항을 측정했다. 결과 지문은 8/8 일치했고, 지연시간은 p50 308.75ms, p95 1,330.87ms였다. 단일 장비에서 고정된 8문항으로 측정한 기준선이므로 운영 처리량이나 전체 API 응답시간으로 해석하지 않는다.

6.4.2 공식 문서 후보 검색

공개 사전 검증 45문항에서 문서 후보 검색기를 비교했다.

검색 방식Top-1MRRRecall@3Recall@5

KURE는 1순위 정확도가 높고 결합 검색은 상위 5개 후보 누락 방지에 유리했다. 다만 이 수치는 공식 문서 후보 검색기의 공개 calibration이며, Router·QueryPlan·DB 교집합·최종 답변까지 포함한 Agent E2E 정확도가 아니다.

6.5 Gold 비접근 블라인드 평가

실행 전에 질문 파일, 소스 commit, Docker 이미지, DB, Schema/Document Dense 색인, 모델 snapshot의 SHA-256을 고정한다. 먼저 Prediction과 journal을 생성해 봉인한 뒤 Gold를 연다. 채점은 한 번만 수행하며 이후 수정 결과는 post-gold development regression으로 분리한다.

평가문항Outcome Exact상품 Precision상품 Recall상품 F1False executionFalse block
Phase 5 최초 Blind10534.29%69.15%25.39%37.14%1건35건

Phase별 문항 구성과 독립성 수준이 다르므로 점수를 단순 추세로 비교하지 않는다. Phase 6는 공식 예시 유사 유형과 과거 회귀 유형이 섞여 독립성 한계가 있다. 최신 Phase 8은 HTTP 200 200/200, timeout·429·5xx 0건, p50 6.34초·p95 13.04초·p99 17.76초였으나, 외부 근거 필요 59문항의 Outcome이 0건이고 정상 질문 79건을 과도하게 차단했다.

상품 Precision 100%와 false execution 0건을 기록해 근거 없는 실행은 억제했다. 반면 안전 경계가 지나치게 보수적으로 작동하면서 Recall과 정상 질문 완결성이 낮아졌다.

우선순위는 안전 기준을 낮추는 것이 아니다. 외부 검색 경로의 연결과 의미상 동등성 판정을 개선해 false block을 줄이면서 false execution 0건을 유지해야 한다.

8.6 핵심 용어

  • Typed QueryPlan: 상품군·필드·조건·정렬·개수의 형식과 허용값이 고정된 실행 계획.
  • Oracle: SQLite/Python으로 정확한 검색·정렬·비교·집계를 수행하는 결정론적 실행기.
  • Verifier: 실행 결과와 답변을 별도 경로로 다시 계산·대조하는 검증기.
  • Schema Dense: 자연어와 DB 필드 설명을 연결하는 KURE 기반 후보 검색.
  • Document Dense: 질문과 승인 공식 문서 단락을 연결하는 KURE 기반 문서 후보 검색.
  • Field-level evidence: 값·단위·품질·원천 행·열·기준일을 상품 단위로 보존한 근거.
  • Release Manifest: 코드·모델·지시문·DB·색인·Docker 이미지를 하나의 배포 단위로 고정한 명세.
  • Fail-closed: 권한·근거·무결성을 완전히 검증하지 못하면 실행이나 결과 반환을 허용하지 않는 정책.

8.7 현재 한계

  • 서로 다른 상품군의 값을 직접 합산하거나 우열·추천으로 판단하지 않는다.
  • 같은 상품군의 2~3개 비교는 지원하지만 3개 비교에서는 차이를 계산하지 않는다. 네 개 이상의 자유형 비교, 교차 상품군 승자 선정, 환율 환산은 지원하지 않는다.
  • 개인 맞춤 투자 추천과 실제 주문은 지원하지 않는다.
  • 공식 외부 근거 경로는 코드가 연결돼 있으나 최신 블라인드에서 Router·QueryPlan 전환 성능이 충분하지 않아 최종 보강이 필요하다.
  • 최신 commit의 Agent Core 전체 회귀와 NCP immutable 재배포·공인 IP smoke가 남아 있다.
  • 현업 유용성과 사업 효과는 독립 사용자 평가와 실제 트래픽에서 별도 검증해야 한다.

이 문서는 2026-09-04 기준 제출용 편집 초안이다. 제출 전 전체 회귀, 독립 평가, immutable Release 생성, NCP 공인 IP 검증 결과를 반영해 상태·수치·endpoint를 최종 확정한다.

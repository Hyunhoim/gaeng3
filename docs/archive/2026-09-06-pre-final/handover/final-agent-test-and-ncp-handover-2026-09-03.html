2. 현재 Agent 흐름

사용자 질문 → SafetyEnvelope → HCX-007 Intent → Ontology·Lexical·Typed Alias Registry → 미해결 의미만 Schema Dense·제한된 HCX Resolver → 서버 Typed QueryPlan 검증 → 제공 DB 후보 고정 → SQLite/Python → 필요 시 공식 외부 검색·Document Dense → 외부 근거와 제공 DB 교집합 → Verifier → HCX grounded answer → Answer Verifier
  • HCLX는 SQL 결과·상품·순위·수치를 바꾸지 못한다.
  • 외부 근거 교집합 없음은 NOT_FOUND, 검증 실패는 CANNOT_VERIFY, 복수 해석은 CLARIFY다.
  • 최종 상품 ID·수치·기간·출처는 서버가 다시 검사한다.

5. Blind 실행 방법

  1. question-only SHA-256 고정.
  2. 코드 commit/diff, DB·model·index SHA 고정.
  3. Gold 비접근 상태에서 preflight.
  4. 공식 GET과 같은 순차 호출로 prediction 생성.
  5. prediction·journal SHA 기록 후 mode 0400.
  6. 그 뒤 Gold를 열어 compare script로 최초 1회 채점.
  7. 이후 실행은 post-Gold regression으로 명시.
python3 fastapi_backend/scripts/run_sealed_lab_blind.py --help
python3 fastapi_backend/scripts/compare_sealed_blind.py \
  --predictions <PREDICTION> --predictions-sha256 <SHA> \
  --gold <GOLD> --gold-sha256 <SHA> --output <SCORE>

Secret·질문·Gold·prediction·journal·score 원본은 Git에 추가하지 않는다.

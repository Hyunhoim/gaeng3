# 금융상품 Agent 사용자 시나리오

상태: 금융 도메인·화면 검수 전 초안

기준일: 2026-07-31

제안서와 데모에서 사용할 사용자 관점의 흐름을 정의한다. 실제 상품명과 수치는
최종 평가용 fixture 또는 최신 허용 데이터로 교체한다.

## 1. 해외 ETF 조건 검색

**사용자 목적**

미국에 상장된 채권형 ETF 중 총보수 조건을 만족하고 AUM이 큰 상품을 확인

**예시 질문**

> 미국에 상장된 채권형 ETF 중 총보수가 0.2% 이하인 상품을 AUM 순으로 5개 보여줘

**Agent 처리**

1. 해외 ETP와 ETF subtype 식별
2. 지역·자산군·총보수·거래 상태 조건을 typed QueryPlan으로 변환
3. SQLite가 필터·정렬·limit 실행
4. Result Verifier가 후보와 순서를 재검산
5. 상품별 보수·AUM·통화·기준일과 원천 필드 표시

**화면 결과**

- 조건 요약
- 후보 수와 상위 5개
- 상품별 비교 가능한 핵심 필드
- 참조 데이터와 기준일

**현재 상태**

Agent Core 검증 완료, 실제 FastAPI·화면 통합 대기

## 2. 국내채권 상세 조회와 데이터 시점 경고

**사용자 목적**

특정 채권의 만기·표면금리·신용등급과 현재 사용할 수 있는 수익률성 정보를 확인

**예시 질문**

> 이 채권의 만기일, 표면금리, 신용등급과 매수수익률을 설명해줘

**Agent 처리**

1. 정확한 종목 식별자가 없으면 먼저 역질문
2. 정적 필드와 동적 필드의 기준일을 분리
3. 오래된 매수수익률·수량은 `stale` 경고
4. 세후수익률을 개인 세제 조건에 맞춘 값으로 재해석하지 않음

**화면 결과**

- 확인된 정적 정보
- 스냅샷 기준 동적 정보와 “현재값 아님” 경고
- 필드별 출처와 기준일

**현재 상태**

Agent Core 검증 완료, 금융 문구 사람 검수 대기

## 3. 같은 상품군 두 상품 비교

**사용자 목적**

관심 있는 같은 상품군 두 상품의 규모·수익률·위험 정보를 한 화면에서 비교

**예시 질문**

> 국내 ETF A와 B의 순자산, 3개월 수익률과 위험등급을 비교해줘

**Agent 처리**

1. 정확한 두 상품을 요청 순서대로 resolution
2. 해당 상품군에서 비교 승인된 필드만 선택
3. 통화·단위·기준일·결측을 필드별 확인
4. 호환되는 수치만 `두 번째-첫 번째` 차이 계산
5. 우수 상품이나 투자 결론을 임의로 결정하지 않음

**화면 결과**

- 두 상품의 원천값
- 계산 가능한 차이와 계산을 차단한 이유
- 결측·stale·기준일 경고

**현재 상태**

같은 상품군 두 상품만 지원. 상품군 간 직접 비교와 세 상품 이상 비교는 미지원

## 4. 복수 상품군 독립 검색

**사용자 목적**

같은 객관적 조건으로 국내 ETF와 해외 ETF를 한 번에 조회

**예시 질문**

> 국내 ETF와 해외 ETF 중 총보수 0.01% 이하인 상품을 각각 3개 보여줘

**Agent 처리**

1. 국내 ETP·해외 ETP를 별도 단일-family QueryPlan으로 컴파일
2. SQLite Oracle·Result Verifier를 상품군별 병렬 실행
3. 한 상품군이 0건이어도 다른 상품군 결과와 근거를 유지
4. 통화 환산·수치 차이·우열 판단은 수행하지 않음

**화면 결과**

- 상품군별 후보 수·상품 목록·근거·기준일
- 결과가 없는 상품군의 `not_found` 상태
- 직접 비교하지 않았다는 안전 안내

**현재 상태**

국내·해외 ETP 공개 실제 데이터 회귀 4/4. 서로 다른 상품군별 조건과 직접
비교는 미지원

## 5. 조건 집계

**사용자 목적**

특정 조건을 만족하는 상품 수 또는 그룹별 규모를 파악

**예시 질문**

> 국내 ETF 중 위험등급별 상품 수를 알려줘

**Agent 처리**

1. AGGREGATE intent와 COUNT·group field 식별
2. 서버가 허용 함수·최대 두 그룹·필드 capability 검증
3. SQLite 결과를 별도 Python Decimal reducer로 재검산
4. 후보 수·유효값·결측값·기준일 표시

**현재 상태**

결정론적 집계 답변 완료. 금액 SUM은 통화 안전 규칙을 통과한 경우만 허용

## 6. 모호한 조건과 금지 요청

**사용자 목적**

“좋은 상품”, “수익이 확실한 상품”처럼 기준이 불명확한 질문을 안전하게 구체화

**예시 질문**

> 앞으로 가장 많이 오를 안전한 상품 하나만 추천해줘

**Agent 처리**

- 미래 수익률 전망과 단정적 추천을 실행하지 않음
- 가능한 경우 상품군·위험 기준·비교할 객관적 필드를 역질문
- 데이터로 확인할 수 없는 조건임을 명시
- Oracle과 답변 LLM을 불필요하게 호출하지 않음

**화면 결과**

- 처리할 수 없는 이유
- 사용자가 선택할 수 있는 객관적 조건 예시
- 투자 권유가 아니라 정보 조회 도구라는 경계

**현재 상태**

공통 Router와 내부 red-team에서 안전 처리 검증 완료

## 데모 선정 기준

최종 데모는 다음 네 장면을 우선한다.

1. 복합 조건 SEARCH와 field evidence
2. 복수 상품군 검색의 부분 결과 보존
3. 비교 또는 집계의 결정론적 계산
4. 모호성·결측·추천 요청의 안전 처리

금융 도메인 담당자는 질문 표현과 위험 문구를, Frontend & Backend 담당자는
실제 화면 단계와 응답 시간을, AI Agent 담당자는 조건·근거·평가 수치를 검수한다.

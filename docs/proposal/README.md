# 기술 제안서 작성 허브

상태: 초안 v0.2 · 8월 6일 설명회 반영

기준일: 2026-08-07

제출 마감: 2026-09-06

이 디렉터리는 팀 전체 기술 제안서와 제출 근거를 관리하는 정본이다.
AI 구현 세부사항은 `finance_agent/docs/`에 유지하고, 이곳에서는 심사위원에게
전달할 주장과 검증 근거를 연결한다.

## 작성 원칙

- 구현 완료, 내부 검증 완료, 외부 확인 대기를 명확히 구분
- 공개 회귀 100%를 독립 blind 일반화 성능으로 표현하지 않음
- 로컬 Qwen 결과를 HyperCLOVA X 또는 공식 평가 결과로 표현하지 않음
- 수치 주장은 [근거 맵](evidence-map.md)에 코드·baseline·문서를 연결
- 목표 아키텍처와 현재 동작하는 아키텍처를 한 그림에서 혼동하지 않음
- 상품군 간 비교, 실제 문서 RAG, FastAPI, HyperCLOVA X는 완료된 범위만 기술
- `think_trace`는 숨은 사고과정이 아니라 도구·검증 결과의 감사 가능한 실행 기록으로 설계

| AI Agent | 데이터·Agent 방법, 평가 근거, 정확성·안전·성능 |
| Financial Domain | 문제 정의, 금융 사용자 시나리오, 표현·리스크·현업 가치 검수 |

## 갱신 절차

1. 구현 또는 평가 결과를 먼저 정본 코드·baseline에 기록
2. [근거 맵](evidence-map.md)에 주장·수치·제약을 연결
3. [기술 제안서 원문](technical-proposal.md)을 짧게 갱신
4. 팀원이 사실성·금융 표현·화면 흐름을 각각 검수
5. 제출 직전 체크리스트와 commit SHA를 동결

제안서용 문서가 구현 문서보다 앞서가면 안 된다. 근거가 없는 내용은
`계획`, `검토 중`, `외부 확인 대기` 중 하나로 표시한다.

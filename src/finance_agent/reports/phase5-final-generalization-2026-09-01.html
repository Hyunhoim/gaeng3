7. 병목 진단 — 수정하지 않음

  1. 과도한 안전 차단: 실행 가능한 96문항 중 35문항을 차단했다. 고난도 30문항에서는 22건이 false block이었다.
  2. QueryPlan filter 보존: filter 정확도 21.51%, ranking 44.57%, limit 42.39%로 조건 구조화 이후의 계획 보존이 가장 약하다.
  3. 복합·교차 실행: 교차 상품군 실행 정확도는 27.27%이며, 2단계·교집합·병렬 조건 유형은 대부분 실행 전에 차단됐다.
  4. 상품 누락: Precision은 69.15%지만 Recall이 25.39%다. 틀린 상품을 다수 추가하는 문제보다 정답 상품을 반환하지 못하는 문제가 더 크다.
  5. 외부 근거 완결성: 외부근거 필요 문항의 문서 존재율은 50%, Outcome은 44.44%다.
  6. HCLX 장애가 주원인은 아님: Intent 105회, 최종 답변 105회, Semantic Resolver 4회가 모두 성공했다. 현재 오답의 주원인은 provider 실패보다 Router·Compiler·QueryPlan·교집합 실행 계약이다.

사용자 요청에 따라 위 병목을 확인만 했으며 Alias 추가, threshold 변경, prompt 변경, corpus 추가, Agent 판단 코드 수정, 재실행을 하지 않았다. 실행 전 변경은 Phase 5 suite metadata와 ID 형식을 허용하는 Blind harness 계약 추가뿐이며 Agent 응답에는 영향을 주지 않는다.

10.5 확인된 병목 — 아직 수정하지 않음

  1. 정상 질문 과잉 차단 12건: 지정 상품 상세 5건, 집단 집계 3건, 기준상품 상대검색·교차 병렬검색·지정상품 비교·단일 정렬 각 1건이다. HCLX가 정상 Intent를 제안해도 서버의 의미상 동등성·복합구문 보존 경계가 너무 엄격한 구간이 남아 있다.
  2. 지정상품 비교의 정렬·완전성: 비교 5문항 Outcome은 20%다. 두 상품을 모두 찾고도 정렬 방향이 반대인 사례, 한 상품만 반환한 사례, 정상 비교를 CLARIFY한 사례가 각각 확인됐다.
  3. 공식 외부근거 Cache Miss: 공식 예시 중 캠브리콘 편입 ETF와 에코프로 자회사 편입 ETF는 계획을 만들었지만 문서를 확보하지 못해 CANNOT_VERIFY로 종료했다. 근거 없이 상품을 반환하지 않는 안전 원칙은 지켰지만 Recall을 잃었다.
  4. 복합 외부검색 뒤 병렬 DB 하위계획 누락: 기간 테마 검색 2건은 ETF 근거와 상품은 맞았지만 함께 요구된 채권 shortlist를 실행하지 않아 상품 Recall이 20%에 그쳤다.
  5. 상품명 내부 단어의 외부관계 오탐: 정확한 상품명에 포함된 테마 표현을 별도 외부지식 요구로 인식해, DB-only 상대검색을 CANNOT_VERIFY로 보낸 사례가 있다. product identity span을 먼저 잠그는 경계가 필요하다.
  6. 채권 잔존일수 기준 불일치: QueryPlan은 맞았지만 Runtime이 만기일과 2026-08-24를 이용해 잔존일수를 다시 계산하면서, 원천 Gold의 remaining_days 값과 2일 차이가 발생했다. 제공 컬럼 우선 원칙과 파생값 표시를 분리해야 한다.
  7. 평가계약 한계 1건: 제한 없이 전체를 요구한 채권 질문은 Gold의 Top-N이 빈 배열인데 Agent는 대표 5개를 반환해 Outcome 오답으로 계산됐다. 후보 수와 필터는 정확하므로, 이 1건은 Agent 오류와 함께 unbounded 결과 채점 계약의 한계로 별도 해석해야 한다.

중요: 사용자 지시에 따라 Phase 6 결과를 확인하고 병목을 분류만 했다. Alias·threshold·prompt·Router·Compiler·Document corpus·SQL·Verifier는 Phase 6 Gold를 본 뒤 수정하지 않았고, 재실행도 하지 않았다.

2. 실제 Agent 구조

질문 → SafetyEnvelope → HCX-007 Intent → Ontology·Lexical → 미해결 의미만 Schema Dense·HCLX Resolver → Typed QueryPlan 검증 → 제공 DB SQL/Python → 필요 시 공식 외부 검색 → 제공 DB 교집합 → Verifier → HCX-007 grounded answer

  • 명확한 조건은 Ontology·Lexical Fast Path로 확정한다. Dense와 HCLX는 미해결 field 후보만 다루며 filter·상품군·정렬·limit·SQL 결과를 바꾸지 못한다.
  • Document Dense는 연구실 profile에서 검토 대기 corpus의 공식 URL 후보만 찾는다. 문서 내용은 매 요청에서 공식 출처로 다시 받아 원문 span·발행일·대상 기간을 검증한다.
  • 외부 근거 상품이 제공 DB와 교차되면 SUCCESS, 교집합이 없으면 NOT_FOUND, 공식 검색을 끝까지 검증하지 못하면 CANNOT_VERIFY, 의미가 복수이면 CLARIFY다.
  • HCLX 최종 답변에는 Verifier가 통과시킨 상품·수치·기간·출처만 제공한다.

5. 이번에 수정한 일반화 병목

  1. 정확 상품 식별자 우선: product_id·ticker·ISIN·정확 상품명 일치가 있으면 더 넓은 프로그램명 substring으로 후보를 다시 확대하지 않는다.
  2. 해외 ticker 오탐 제거: 문서의 일반 영단어를 대문자로 바꿔 RIC처럼 해석하지 않는다. 공식 문서가 실제 대문자로 쓴 상품 문맥 token만 허용한다.
  3. 공식 영문 철자 보수적 복구: HCLX 별칭이 틀려도 공식 문서에 반복 등장하는 고유명사 철자를 음차 유사도·유일성으로 후보화한다. 이후에도 동일 원문 안의 관계 signal과 제공 DB 상품 identity가 모두 있어야 실행한다.
  4. Comparator 공개 식별자 정합성: 해외 ETF는 내부 key 대신 field evidence의 공식 ticker를 Gold와 대조할 수 있게 했다.
  5. 외부 문서 성능: 전체 제공 DB를 chunk마다 반복 탐색하지 않고 문서 단위 상품 후보를 먼저 좁혀, 과거 300초 이상 걸리던 대표 PDF 경로를 일반적으로 수십 초 이내로 줄였다.
  6. 근거 없는 축소 답변 금지: 공식 문서 또는 DB 교집합이 완성되지 않으면 일부 조건을 버리고 상품을 반환하지 않는다.

6. 남은 핵심 병목

  1. 교차 상품군 복합 QueryPlan: Phase 3 후검증 false block 40건 중 34건이 여러 상품군·여러 절을 함께 처리하는 compiler 경로다. 다음 최우선은 2–4개 subquery를 일반화해 조립하는 Typed QueryPlan compiler다.
  2. 정렬·filter 보존: 전체 v20에서 상품 순서 불일치 77건, filter 불일치 61건이 남았다. 같은 field의 단위·0/결측 제외·상품군별 별칭을 SQL Oracle과 재대조해야 한다.
  3. 외부 PDF 최대 지연: 대형 PDF 원문을 요청마다 다시 검증하는 안전성은 유지하되, 승인 snapshot·문서 hash 기반 extraction cache를 Release Manifest에 결합해야 한다.
  4. 공식 corpus 승인: 현재 pending corpus는 URL 후보 검색에만 사용한다. 실제 evidence cache로 production ON하려면 데이터 권리·금융 검토와 corpus/index/Relation Store SHA-256 승인이 필요하다.
  5. 새 미공개 평가: 이번 후검증 규칙을 동결한 뒤, 교차 상품군과 외부 근거를 포함한 새 unopened 질문으로 일반화 성능을 다시 측정해야 한다.
